# Arrow Nexus Unity Implementation Guide

This guide explains how to open the project in Unity, get it running immediately, and then turn the runtime bootstrap into a proper authored scene.

## Current Project Status

The repo is now set up as a Unity project with:

- `Packages/manifest.json`
- `ProjectSettings/ProjectVersion.txt`
- A runtime bootstrapper at `Assets/Scripts/Core/GameBootstrapper.cs`

The bootstrapper can create a playable maze scene automatically when you press Play in an otherwise empty scene.
It also creates a small on-screen control guide so first-time players can learn the inputs immediately.

## Recommended Unity Version

Use Unity `2022.3.20f1` or another `2022.3 LTS` editor if possible.

## Required Unity Modules

Make sure these built-in modules are enabled in the project:

- `Physics 2D`
- `Tilemap`
- `Particle System`

The project manifest now includes them, but if Unity still shows missing-type errors after import, open Package Manager and confirm those modules are installed.

## What The Bootstrapper Does

When no existing `PlayerArrow` or `TileManager` is present in the scene, the bootstrapper creates:

- Core managers
- A `Grid`
- Ground and overlay tilemaps
- A procedural maze grid
- A player arrow
- A main camera
- Basic meta managers like HUD, audio, FX, and pulse timer

This means you can test the project without building the scene by hand first.

## Fastest Way To Run

1. Open the folder in Unity Hub.
2. Let Unity import the project.
3. Open any empty scene or create a new blank scene.
4. Press Play.

If the scene is empty, the bootstrapper should build the runtime world for you.

## Proper Authoring Workflow

If you want a clean production scene instead of runtime-generated setup, build it manually in the editor.

### 1. Create The Main Scene

Create a new scene and save it as something like:

- `Assets/Scenes/Main.unity`

### 2. Create The Scene Hierarchy

Recommended hierarchy:

- `Systems`
- `Grid`
- `Player`
- `Camera`
- `Canvas`

### 3. Add Core Manager GameObjects

Create empty GameObjects and add these scripts:

- `InputManager`
- `GameStateManager`
- `SaveSystem`
- `CollisionSystem`
- `TileManager`

Optional systems:

- `CameraController`
- `FXManager`
- `AudioManager`
- `AdaptiveDifficultyEngine`
- `PulseTimer`
- `HUDManager`
- `DailyChallengeSystem`
- `GhostSystem`
- `SpeedrunSystem`
- `MonetizationManager`

### 4. Build The Tilemap Setup

Under `Grid`, create:

- `Ground Tilemap`
- `Overlay Tilemap`

Assign them to `TileManager`.

`TileManager` also needs tile assets for:

- Wall
- Path
- Start
- Goal
- Hazard
- Signal Node
- Secret Path
- Speed Zone

### 5. Create The Player

Create a `Player` GameObject and add:

- `SpriteRenderer`
- `BoxCollider2D`
- `Rigidbody2D` set to Kinematic
- `PlayerArrow`

Then call `Initialise(startCell)` after the maze is built, or let the bootstrapper handle it at runtime.

### 6. Create The Camera

Use a `Main Camera` with:

- `Camera`
- `CameraController`

The camera follows the player and zooms based on momentum.

### 7. Create The HUD Canvas

Add a `Canvas` and wire these references into `HUDManager`:

- Momentum fill image
- Combo text
- Pulse ring image
- Death screen
- Level complete screen

### 8. Control Guide

The runtime bootstrapper also creates a small control guide overlay with:

- Movement keys
- Dash key
- Ability key
- Pause key
- Goal reminder

It fades out automatically once you start interacting with the game.

### 8. Add Maze Content

The maze is generated by `MazeGenerator`, then rendered by `TileManager`.

If you want to use handcrafted content later, create `LevelDatabase` assets and point them at grid data files.

## Inspector Wiring Checklist

Make sure these references are assigned:

- `TileManager`
  - Ground Tilemap
  - Overlay Tilemap
  - Tile assets
- `CameraController`
  - Optional minimap camera
- `HUDManager`
  - Momentum fill
  - Combo text
  - Pulse ring fill
  - Death screen
  - Level complete screen
- `PulseDoors`
  - Door cells
  - Door sprites
- `SignalNode`
  - Target pathway or hazard or section
- `TeleportNode`
  - Linked node

## Input Setup

The project uses legacy Unity input checks:

- `WASD`
- Arrow keys
- `Space`
- `Shift`
- `Escape`

For mobile:

- Swipe detection is already handled in `InputManager`

No extra Input System package is required for the current code.

## Tags And Physics

The project is now component-driven instead of depending on a `Player` tag.

Still make sure the player object has:

- A collider
- A `Rigidbody2D`
- `PlayerArrow`

## Minimal First Test

After import and scene setup:

1. Press Play.
2. Confirm the maze appears.
3. Confirm the player is visible.
4. Press `WASD` or arrow keys to move.
5. Press `Space` to dash.
6. Check that the HUD and camera respond.

## Troubleshooting

### Nothing Spawns

- Make sure you pressed Play in Unity, not just opened the folder.
- Check that the scene does not already contain a conflicting bootstrap object.

### Player Does Not Move

- Confirm `InputManager` and `CollisionSystem` exist.
- Confirm the player has `PlayerArrow`.
- Check the Console for missing reference errors.

### Tiles Do Not Appear

- Make sure `TileManager` has both tilemap references.
- Verify the tile assets are assigned.

### Missing Unity Types

- If you see `Collider2D`, `Tilemap`, or `ParticleSystem` errors, reopen Package Manager and confirm the built-in modules above are installed.
- Reimport the project after Unity finishes syncing packages.

### HUD Is Empty

- Assign the UI references in `HUDManager`.
- Make sure TextMeshPro is installed.

### Control Guide Does Not Appear

- Confirm `ControlGuideOverlay` exists in the scene or is spawned by the bootstrapper.
- Check that the game is running in a blank scene, not an already-authored scene that bypasses bootstrap creation.
